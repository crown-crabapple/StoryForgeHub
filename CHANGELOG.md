# Changelog

All notable changes to StoryForge are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as described in [docs/compatibility.md](docs/compatibility.md).

## [Unreleased]

### Added

- **Read view.** The Manuscript tab has a fifth view, **Read** (`?view=read`): the whole manuscript as one continuous page for reading and reviewing, with act and chapter headings, `* * *` between scenes, a sticky bar (go to chapter, scene titles on/off, notes on/off, "Scene 3 of 40 · 12% · 2 h left") and an **Edit** link on each scene that opens it in Write. The rail marks the scene you are reading and a click on a scene scrolls there; Write and Read keep your place when you switch, and each book remembers where you stopped reading (in the browser only). Read only: nothing is written.
- **M12: an AI can work through a book.** Each book has an **AI level** (Settings, **AI level**; `preferences.ai.level` in `book.md` or `library.md`): `off` (read only), `advisor` (suggest edits, create tasks), `planner` (also plan, canvases, workspace docs, ledgers, state, the writing log, finding dismissals) and `cowriter` (also create chapters and scenes). It caps every MCP connection and plugin token whatever the token was granted: a write above the level is `403 AI_LEVEL` and nothing is written. A book that sets none is `planner`, which is what connections could already do. Only the owner sets it (`POST /api/books/:b/ai-level`); `GET /api/v1/books` and `codex_status` show each book's `ai_level`. Two new token permissions, off by default: `workspace` (**Connect Claude**: "Workspace docs and ledgers") and `draft` ("Create chapters and scenes"). A new `workspace` module (**AI Workspace**) gates the workspace routes. See [docs/contracts/M12-ai-workspace.md](docs/contracts/M12-ai-workspace.md).
- **M12: workspace docs, ledgers and state.** Workspace docs under `planning/workspace/`, `planning/state/chapter-NN/` and `planning/development/` (kind `doc`, schema `storyforge.doc/v1`, with `workspace`, `chapter` and `locked`): the book settings, the style guide and per-chapter state, with sha-checked saves, append, lock (an AI connection can lock but never unlock), archive, restore and a setup call for the starter docs. A scene gets a `cast` (`entry` and `role`: `pov`, `appears` or `mentioned`) and an `origin` (`ai` or `author`); a task gets `for` (`ai` or `author`); a timeline `learns` item can keep the fact's full wording as `fact`; `activity/writing-log.md` gets an optional `AI words` column. The ledger of promises, questions and clues, the chapter cast, what a character knows by a chapter and the state events (`Chapter N (state)` events) are readable and writable through the plugin API (`/api/v1/books/:b/ledger`, `/cast`, `/knowledge`, `/state-events`, `/tasks`, `/workspace/docs`, `/activity/ai-words`) and 23 new MCP tools (9 read, 14 `workspace`). No file is deleted: ledger items retire by status and a state ends by a later item.
- **M12: continuity for chapter-by-chapter writing.** New rules `CS1` (a character on the page after dying, in a scene cast as `pov` or `appears`), `CS2` (a destroyed or lost object used) and `TH2` (a promise or question open more than `overdue_chapters` chapters after its setup, default 12). `GET /api/books/:b/continuity?chapter=N&cast=<entry>:<role>,...` checks a planned cast before the chapter is written. The author's settings live in `planning/continuity/settings.md` (`overdue_chapters`, `severity` per rule: `error`, `warning`, `info` or `off`) and have no plugin route. A connection can run the check, dismiss a finding with a reason and restore it (`codex_continuity_check`, `codex_dismiss_finding`, `codex_restore_finding`).
- **M12: the co-writer.** With the `draft` permission at level `cowriter`, a connection can create a chapter (`codex_create_chapter`), add scenes (`codex_create_scene`) and revise its own unaccepted draft (`codex_save_draft`). A scene it creates is always `origin: ai` with status `drafting`; the author accepts it by changing the status, and while it is still `drafting` `codex_save_draft` can replace its body (`403 NOT_AI_DRAFT` for any scene that is not an unaccepted AI draft). The words are added to the AI words of the writing log. `GET /api/v1/books/:b/context?chapter=N` and `codex_get_context` give one chapter's context pack (workspace book and style docs, story plan, scene plans, cast, what the characters know, open promises and clues, state, the last scene's tail, continuity findings) trimmed to a character budget (default 24000) in priority order, with `truncated` naming what was cut. The index schema is now version 4 (`scenes.origin`); an older index is rebuilt.
- **M12: AI Activity.** Every write made through a plugin token records the connection in the op journal. `GET /api/books/:b/ai-activity` lists the changes newest first; each has **Undo** (`POST /api/books/:b/ops/:opId/restore`), or **Archive** for a chapter or scene a connection created, since a created file cannot be undone. The `storyforge-chapter-loop` skill (`skills/storyforge-chapter-loop/`) and the guide [docs/ai-workspace.md](docs/ai-workspace.md) describe the plan, approve, draft, check, record loop.
- **M11: an AI can change the Story Plan.** A new token permission, `plan`, lets an MCP connector or plugin token write your Story Planner items: the story plan, scene plans, links, structures and beats, arcs and milestones, relationships and developments, clues and who learns them, and synopses (only files under `planning/`; never prose, scenes or Codex entries). It is off by default: **Connect Claude** has a new "Change the plan" option and **Settings, Plugins** lists the permission in words. Writes run through the app's own planner routes, so they use the same checks, a stale `base_sha256` is a conflict, and the author can Undo each change. API v1 adds `POST /api/v1/books/:b/plan/...` (needs `plan`; the Story Planner and Integrations modules on), and the plan reads keep each item's `sha256` (still no file paths) so a write can send it back; new reads are `GET /plan/scene-plans/:sceneId`, `GET /plan/check` (PL1 to PL6) and `GET /plan/templates`. MCP adds 30 plan write tools (`codex_save_story_plan`, `codex_save_scene_plan` and `codex_create_*`, `codex_update_*`, `codex_archive_*`, `codex_restore_*`, `codex_set_beats`, `codex_set_arc_milestones`, `codex_set_relationship_developments`, `codex_set_clue_knowers` for links, structures, arcs, relationships, clues and synopses), 3 read tools (`codex_get_scene_plan`, `codex_get_plan_check`, `codex_list_structure_templates`) and `codex_add_plan_cards`, which puts story cards on a canvas for a list of ids. The canvas tool descriptions now name the planner card kinds. Not offered: a scene plan's notes and dry runs in the MCP tools. See [docs/contracts/M11-ai-plan-tools.md](docs/contracts/M11-ai-plan-tools.md), [docs/mcp.md](docs/mcp.md) and [docs/api.md](docs/api.md).
- **M10: the Plan tab is a canvas.** There is one **Plan** tab and no Canvas tab; `/books/:id/canvas` goes to `/books/:id/plan`. The tab is shown when the Story Planner or the Board feature is on. With the planner on, the canvas is where you plan: a **Plan layers** rail (Links, Beats, Arcs, Clues, Relationships, each with a count), a **Structure** picker and a **Branch** (what-if) choice, none of which changes the saved file. Story cards can now point at the story plan, a structure, a beat, an arc, a relationship, a synopsis or a clue. A **beat column** is a column whose card is a beat: drop a scene card in it to add the scene to the beat, drag it out to remove it, or press **Tidy to plan** to move scene cards into the column of their first beat. Scene cards show badges for their beats, clues planted or revealed and arc milestones; clue cards are joined to scenes by `plants` and `reveals` edges, a reveal before its plant is drawn in the warning colour, and Connect between a scene and a clue asks whether it plants or reveals. The **Inspector** shows the picked card's plan (a scene's beats are checkboxes), **Edit plan** opens the existing Story plan, beat sheet, arc, relationship, synopsis, clue and scene editors in a side drawer, and the toolbar has **Cause**, **Clue**, **Arc**, **Relationship** and **Beat** tools. The **Plan check** list in the rail shows PL1 to PL6; clicking one selects its cards, and findings carry a new `related` list of the ids they touch. A book with no canvas offers **Build your plan canvas** (`planning/canvases/story-plan.canvas`: a column per beat of the primary structure, your scenes, clues, arcs and the links between scenes). **List** mode shows the same plan as plain lists you can use with the keyboard or a screen reader, and starts by default on a narrow screen. Links such as `/plan?select=<id>` open the canvas with that card picked, and the older `?view=` forms of the Plan tab still land on the canvas. A series plan opens from a **Series plan** button. Canvases can be saved when either the Board or the Story Planner feature is on. Viewers, reviewers and share links see the canvas, its plan and List mode read only. Not done: an arc lanes layer, the relationship graph and the SVG downloads on the Plan tab, and choosing a what-if branch for a link made on the canvas. See [docs/contracts/M10-plan-canvas.md](docs/contracts/M10-plan-canvas.md).
- **Story Planner M8: clues, what-if branches, series view and planning export.** The Plan tab has a **Clues** view (`?view=clues&clue=<slug>`): a list of facts with an editor (the fact, its kind of clue, reveal or secret, the scenes where it is planted, the scene where it is revealed, a red-herring flag and notes), a list of who knows it in which scene (the reader or a character, and whether they believe something false), and a **Clues by scene** grid that marks P (planted), R (revealed) and K (someone learns it) for each scene in reading order. A scene can tell the reader something the protagonist does not know: add a reader knower and leave the character out. Clues are kept apart from a scene's `knows` and `learns`. **Flow** has a **Branch** filter (Main plan, each branch, All); links of a what-if branch are drawn dotted, and **Connect** and the link panel have a **Branch (what-if)** field (empty means the main plan). **Flow** and the relationship **Graph** mode in Lanes (new: entries on a circle, relationships as lines labelled with their end state) have **Download SVG**, a standalone file made on this computer. The Plan Overview has a **Series** section for a book in a series: each book in order with its logline and overview synopsis, and the shared characters across books (read only; in shared mode a member sees only the books they may read, and a note says how many were left out). The Export dialog has **Planning notes (Markdown zip)**: the story plan, outline, characters, primary structure, synopses, clues and links as Markdown files; the manuscript exports never include planning. The review queue shows `PL5` and `PL6` and opens the clue. Creating, archiving and restoring a clue can be undone.
- **Story Planner M8 (storage and internal API):** clues (`planning/clues/<slug>.md`, schema `storyforge.clue/v1`: required `slug` and `fact`; optional `kind` (`clue`, `reveal` or `secret`), `planted` (scene ids), `revealed` (a scene id), `red_herring` and `knowers`, a list of `{ who, scene, how?, reliable? }` where `who` is an entry id or `reader`); a bad shape is `E102`, an unknown scene or entry `E301`, an archived one `W303`, an unknown knower key `I401`. Links gain an optional `branch` (a slug of at most 40 characters; a bad one is `E102`); `W316` now compares `from`, `to`, `relation` and `branch`, and the duplicate refusal on write (`REFUSED_DUPLICATE_LINK`) does the same. Internal routes `GET /api/books/:b/clues`, `GET /api/books/:b/clues/:slug`, `GET /api/books/:b/series-plan` (`{ series: null }` for a book in no series; `hidden` counts books a member may not read), `GET /api/books/:b/export/planning` (a zip; policy class `read`, not available to a share link) and `POST` for clues (create, update, knowers, archive, restore; dry run, a sha check, writes need the `planner` feature); `POST` to create or update a link accepts `branch`; `GET /api/books/:b/flow` has `branches` and each edge a `branch`, and `GET /links` items have `branch`. See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md).
- **Story Planner M8 (review engine):** the rules `PL5` (info: a clue of kind `clue` with planted scenes, no revealed scene and not a red herring) and `PL6` (warning: a clue revealed in a scene that comes before its first planted scene) in `GET /api/books/:b/continuity`, with the same exceptions and **Make a task**. `PL1` and `PL2` read only the main plan, so a what-if branch never adds a finding.
- **Story Planner M8 (plugin API v1 and MCP, read only):** `GET /api/v1/books/:b/plan` and `GET /api/v1/books/:b/plan/{links,arcs,structures,relationships,synopses,clues}` (permission `read`, a granted book, the Story Planner module on or `403 MODULE_OFF`; no file paths or hashes in the answers), and 7 read tools: `codex_get_plan`, `codex_list_plan_links`, `codex_list_arcs`, `codex_list_structures`, `codex_list_relationships`, `codex_list_synopses`, `codex_list_clues`. Plugins and MCP cannot write planner data. See [docs/api.md](docs/api.md) and [docs/mcp.md](docs/mcp.md).
- **Story Planner M7: Synopsis Studio.** The Plan tab has a **Synopsis** view (`?view=synopsis&synopsis=<slug>`): a list of the book's synopses (premise, logline, elevator pitch, short, one page, long, chapter treatment or custom) with the word count against the target and a **Sources changed** badge, and an editor. **Build from plan** proposes text built only from the story plan, scene summaries and the primary structure's beats (never from prose); you see the proposal against your text as hunks and **Accept** or **Decline** each one, then save. **Keep my text** marks the new sources as reviewed without changing your text. Nothing is written until you save, and a change made elsewhere meanwhile is a conflict, not an overwrite. **Ask AI** is shown only with the AI module on and a provider set: it opens the existing AI workshop (preview, Send, and the cloud confirmation); the reply only becomes a proposal and is never saved automatically. Creating a synopsis can be undone.
- **Story Planner M7 (storage and internal API):** synopses (`planning/synopses/<slug>.md`, schema `storyforge.synopsis/v1`: required `slug` and `type`; optional `name`, `target_words` and `basis`, the sha256 of the extracted text last reviewed); a bad `type`, `name`, `target_words` or `basis` is `E102`; internal routes `GET /api/books/:b/synopses`, `GET /api/books/:b/synopses/:slug`, `GET /api/books/:b/synopses/:slug/extract` (offline, writes nothing; `{ text, basis, skipped }`) and `POST` to create, update, archive and restore (dry run, a sha check, writes need the `planner` feature). See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md).
- **Story Planner M6: the review engine.** Four plan checks join the continuity queue, with the same sources, exceptions and **Make a task**: `PL1` (a scene that is not in the flow; only when the book has a live link), `PL2` (two neighbouring scenes with links but no direct link, "not documented in the planner"), `PL3` (a beat in a live structure with no scenes; omitted beats are skipped) and `PL4` (a thread with payoff scenes but no setup scenes). The queue has a **Family** filter (All, Story facts, Plan; `?family=plan` or `?family=facts` in the URL). The Acknowledge dialog has **This is on purpose**, and those findings are labelled **Intentional**. A `PL3` source opens the structure in the Plan tab. The Plan Overview has a **Review** card with the number of plan notes, linking to the queue filtered to Plan. The Plan tab uses the full page width.
- **Story Planner M6 (storage and internal API):** the rules `PL1` to `PL4` in `GET /api/books/:b/continuity` (no new route); continuity exception files accept an optional `intentional: true` (a value that is not a boolean is `E102`); `POST /api/books/:b/continuity/exceptions` accepts an optional boolean `intentional` (`400` if not boolean); `suppressed[].exception` has `intentional` (boolean). See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md).
- **Story Planner M5: lanes, relationships and planner data on the Board, Outline and Matrix.** The Plan tab's **Arcs** view is now **Lanes**: one row per character arc, relationship or plot thread across the scenes in reading order, with a checkbox per kind (remembered in this browser). Arc milestones are diamonds, relationship developments are round markers, and plot thread entries are squares marked S, D or P. Below 768px only the list is shown. A relationship opens in a side panel (**New relationship…** picks two Codex entries): baseline and end state save on their own, notes have a Save button, and developments (a scene, the change, and how each side sees the other) are saved together with **Save developments**. Archived relationships can be restored from the Lanes view, and the scene inspector's Plan section lists the relationship changes in that scene. In **Flow**, a link can start or end at a beat of a live structure: the Connect dialog has a **Beats** group, and beats that have a link show in the graph, in the list and in a Beats section. The **Board** has a **Card face** menu (purpose, links in and out, beats, arc milestones, missing summary or goal) and an **Arc** filter. The **Outline** has a **Plan** column with an **Open in Plan** link, **Arc** and **Beat** filters, and **Group by** chapter or beat of the primary structure. The **Matrix** can show a column per arc (milestones) and per beat of the primary structure. Every change has Undo; scenes and Codex entries are never written.
- **Story Planner M5 (storage and internal API):** relationships (`planning/relationships/<slug>.md`, schema `storyforge.relationship/v1`: two Codex entries of any type, baseline, end state, free notes, and an ordered list of developments that each name a scene and a change, with how each side sees the other); one live relationship per pair of entries; new diagnostics `E212` (a relationship of an entry with itself) and `W320` (two live relationships for one pair), and development checks `E102`, `I401`, `E301` and `W303`; a link's `from` and `to` can be a beat id inside a structure (`W303` when the structure is archived); links answer `from_kind` and `to_kind`, and `flow` adds a node for each beat that a live link uses; removing a beat that a link uses, archived links included, is refused with `REFUSED_BEAT_LINKED`; internal routes `GET /api/books/:b/relationships`, `GET /api/books/:b/relationships/:slug` and `POST` to create, update, set developments, archive and restore (dry run, a sha check, Undo; writes need the `planner` feature), and `GET /api/books/:b/plan-badges` (the planner data of every scene in one read); `relationships` added to the `plan-overview` counts. See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md).
- **Story Planner M1 (storage and internal API, no screen yet):** causal links between scenes (`planning/links/<slug>.md`, schema `storyforge.link/v1`) and per-scene planning fields (`planning/scene-plans/<scene-slug>.md`, schema `storyforge.scene-plan/v1`); new diagnostics `E211`, `W316` and `W317`; internal routes under `/api/books/:b/` (`links`, `scene-plans`, `flow`) with dry run, a sha check, archive, restore and Undo; a new `planner` feature in Settings. The routes are not part of plugin API v1. See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md). Decision: [docs/decisions/0003-story-planner.md](docs/decisions/0003-story-planner.md).
- **Story Planner M2: the Plan tab.** A new **Plan** tab (feature `planner`) with **Overview** (the story plan fields, how many scenes have a plan or a link, the scenes not linked yet) and **Flow** (the causal links between scenes as a list and, on wider screens, a graph laid out by manuscript order). Connect two scenes with a relation and a reason (previewed first), then edit, reverse, archive or restore a link, each with Undo. The list is the full keyboard and screen-reader equivalent of the graph; below 768px only the list is shown. Moving a scene in the manuscript never changes its links.
- **Story Planner M2 (storage and internal API):** the book's story plan (`planning/story.md`, schema `storyforge.story-plan/v1`: premise, logline, theme question, central conflict, protagonist goal, stakes, protagonist, and free notes); new diagnostic `W318` (a live story plan anywhere but `planning/story.md`); internal routes `GET /api/books/:b/story-plan`, `GET /api/books/:b/plan-overview` and `POST /api/books/:b/story-plan` (dry run, a sha check, Undo; writes need the `planner` feature); a **Plan** section in the scene inspector (feature `planner`). See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md).
- **Story Planner M3: arc screens.** A character's Codex page has an **Arc** panel: start an arc for this book, set its type and fields (want, need, false belief, fear, wound, starts as, ends as), and list its milestones in order, each tied to a scene (add, move up or down, remove, then Save milestones). The Plan tab has an **Arcs** view: one lane per character across the scenes in reading order (on wider screens) and a list with every milestone; archived arcs can be restored there. The scene inspector's Plan section lists the arc milestones set in that scene. Every change has Undo; Codex entries and scenes are never written.
- **Story Planner M3 (storage and internal API):** character arcs (`planning/arcs/<slug>.md`, schema `storyforge.arc/v1`: arc type, want, need, false belief, fear, wound, start and end state, free notes, and an ordered list of milestones that each name a scene); one live arc per character per book, pointing at the Codex entry by id; new diagnostic `W319` (two live arcs for the same character), and milestone checks `E102`, `I401`, `E301` and `W303`; internal routes `GET /api/books/:b/arcs`, `GET /api/books/:b/arcs/:slug` and `POST` to create, update, set milestones, archive and restore (dry run, a sha check, Undo; writes need the `planner` feature); `arcs` added to the `plan-overview` counts. See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md).
- **Story Planner M4: structure screens.** The Plan tab has a **Structure** view: one tab per structure with the primary one marked, and a **New structure** dialog that shows a template's beats before you apply it. The beat sheet editor edits, reorders, adds and removes beats, marks them done or omitted, and assigns scenes by search (then Save beats). The scene inspector's Plan section has **Beats in this scene**. The Overview shows the structure count and the primary structure, which you can set from the Overview or the Structure view. Every change has Undo; scenes are never written.
- **Story Planner M4 (storage and internal API):** story structures (`planning/structures/<slug>.md`, schema `storyforge.structure/v1`: name, template, template version, free notes, and an ordered list of beats with name, purpose, question, position, a state of open, done or omitted, and scenes); a book can have any number of structures; eight built-in templates (`three-act`, `five-act`, `heros-journey`, `seven-point`, `story-circle`, `mystery`, `romance`, `custom`) whose beats are copied into the new file; a new story plan field `primary_structure`; beat checks `E102` (including a beat id used twice), `I401`, `E301` and `W303`, and `E301` and `W303` for `primary_structure`; internal routes `GET /api/books/:b/structure-templates`, `GET /api/books/:b/structures`, `GET /api/books/:b/structures/:slug` and `POST` to create, update, set beats, archive and restore (dry run, a sha check, Undo; writes need the `planner` feature); `structures` and `primary_structure` added to `plan-overview`. See [docs/format.md](docs/format.md) and [docs/api.md](docs/api.md).
- **Canvases for plugins and Claude:** a new token permission `canvas` lets API v1 and MCP list, read, create, edit, archive and restore canvases (`/api/v1/books/:b/canvases`, 7 new `codex_*_canvas` tools); writes use the same sha check as the app, and Connect Claude has a new "may edit canvases" option (off by default). See [docs/mcp.md](docs/mcp.md) and [docs/api.md](docs/api.md).
- **MCP service:** `POST /mcp` (Streamable HTTP, bearer plugin token, JSON replies, no SSE or session) and `storyforge mcp`, a stdio bridge to the running server, for Claude Code and Claude Desktop. 14 tools named like the legacy `codex_*` tools (11 read, 3 propose); writes are proposals the author accepts or rejects. See [docs/mcp.md](docs/mcp.md).
- **Connect Claude** in Settings: create an MCP token for Claude (name, books, may suggest), shown once with ready-to-copy setup; list and revoke connections.
- **Canvas** (`/books/:id/canvas`): infinite visual boards for mood images, colour swatches, Markdown notes, to-do lists, web links, columns, groups and labelled arrows, plus live story cards for scenes, Codex entries, threads, events and notes that follow the book. Each canvas is a JSON Canvas file (`planning/canvases/<slug>.canvas`, Obsidian-compatible) saved through the store; the scroll wheel zooms; keys are in the shortcut registry. Contract: [docs/contracts/M09-J01-canvas.md](docs/contracts/M09-J01-canvas.md).
- **Per-book access for members** (shared mode): All books with one role, or Only these books with a role per book, for members and invites. A limited member cannot open, search or list other books; shared series data needs all-books access to change.

### Fixed

- **Codex entries show their Markdown.** The Details tab of an entry drew each section's text as written, so lists, `**bold**`, `*italic*`, `###` headings and tables showed their Markdown marks. Sections are now drawn as Markdown (CommonMark with GFM tables, task lists and strikethrough, read only; raw HTML shows as text and images are not loaded). A `[[link]]` in a section now opens the entry, as it already did in the facts grid; a web link opens in a new tab.

## [0.1.0]

The first release: milestones M00 to M08, grouped by feature family (F01 to F20 in the feature register). Known limits are in [docs/release-notes/0.1.0.md](docs/release-notes/0.1.0.md).

### Added

- **F01 Projects and library:** a library of book folders, series and pen names, new-book templates, covers (an image or a generated colour cover), book metadata and archiving; portable project and series files; a library view that finds every book under the library folder.
- **F02 Editor and reading surfaces:** a Markdown editor with a live preview, themes (including light and high contrast), focus mode, keyboard-first operation, comments, revision history, an offline save queue in shared mode, and layouts that work from a phone to a wide desktop screen.
- **F03 Structure:** series, book, act, chapter and scene, boards, an outline, a matrix view and scene metadata; deterministic order that comes back the same after an index rebuild; safe scene insert, move and renumber.
- **F04 Codex:** characters, places and things with types, custom fields, images, aliases, relations and mentions; entries shared across the books of a series; readable entity files and an indexed graph.
- **F05 Characters and arcs:** appearance, point of view, knowledge and state tracking per scene, with charts and findings that point back to their source files.
- **F06 Worldbuilding:** maps, systems and history as Codex material and shared world templates, portable as plain files.
- **F07 Plot and timelines:** beats, threads with setup and payoff, and narrative and chronological timelines as linkable records.
- **F08 AI provider management:** optional provider profiles for a local or cloud model, token and context controls, a disclosure of whether a provider is local or cloud, credentials kept in a key store, and zero network traffic until a provider is configured.
- **F09 AI writing assistance:** rewrites shown as selectable before-and-after diffs; nothing is written until the author accepts.
- **F10 AI workshop:** chat scoped to the project, a book, a scene or a selection, with an exact context preview, Send, and saved local history.
- **F11 Analysis and revision tasks:** scene, chapter and manuscript checks and revision tasks whose findings carry evidence.
- **F12 Continuity engine:** five rule families (fact conflicts, timeline, knowledge, possession and location, threads) that open the exact source lines, with stable fingerprints and exceptions kept as Markdown files.
- **F13 Notes and research:** notes, research, assets, links, tags and non-canon material kept apart from the manuscript, with relative file links and search.
- **F14 Goals and sessions:** word goals, sessions, streaks, timers and a progress dashboard from project-local activity records.
- **F15 Analytics:** rebuildable charts and an Insights dashboard computed from the files and the index.
- **F16 Import, export and backup:** export to Markdown, Word, EPUB and PDF; portable backup and restore; a legacy StoryForgeHub importer with a dry run, a rehearsal into a new folder, reconciliation and a byte-for-byte compare; deterministic output.
- **F17 Shared mode:** an optional server layer with accounts, roles, invites, read-only share links, comments, suggestions, an audit log with a hash chain, conflict handling (`409 STALE` keeps the losing text as a suggestion) and rate limits; the Markdown files stay the authority.
- **F18 Extensions:** themes, layout and prompt customization, feature modules, plugin manifests, API v1 with scoped read, propose and events tokens, and signed webhooks (separate programs; StoryForge never runs plugin code), with two sample plugins.
- **F19 Open source and operation:** the AGPL-3.0-only licence, launchers for Windows, macOS and Linux, Docker, Compose, systemd and Caddy files, an owner password reset command, no telemetry and no paywalls, accessibility and performance work with `npm run bench`, one-command CI (`npm run ci`) with a GitHub Actions workflow, a deterministic versioned release zip, and contributor, security and release documentation.
- **F20 Receipts:** a hash-linked provenance ledger of author, AI and outside changes with lineage, per-line origin, an integrity check and an exportable evidence pack; receipts are private and make no legal claim.
